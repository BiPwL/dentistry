# Запрос на разработку: веб-приложение для стоматологической клиники

## Задача
Разработай полнофункциональное веб-приложение для стоматологической клиники: схему базы данных, серверную часть, клиентскую часть и тестовые данные. Всё должно работать локально на OpenServer.

---

## 1. Технологический стек

### Клиентская часть
- HTML5, CSS3
- Bootstrap 5.3 (адаптивная сетка; корректное отображение на десктопе и мобильных устройствах)
- Нативный JavaScript (без сторонних JS-фреймворков и сборщиков)

### Серверная часть
- PHP 8.2 без использования сторонних фреймворков
- Доступ к данным — через PDO
- Отправка email через PHPMailer с SMTP

### База данных
- MySQL 8.2
- Схема импортируется через phpMyAdmin (также запущенный в OpenServer)

### Окружение
- OpenServer (локальный веб-сервер)

---

## 2. Требования к безопасности

| Требование | Реализация |
|---|---|
| Хранение паролей | Только bcrypt-хеши, `cost = 12` |
| SQL-инъекции | Все запросы — через подготовленные выражения PDO; прямая подстановка пользовательского ввода в SQL исключена |
| CSRF | Все формы, изменяющие состояние системы, защищены CSRF-токенами с проверкой на сервере |
| XSS | Любой пользовательский ввод, выводимый в HTML, экранируется через `htmlspecialchars()` |
| Контроль доступа | К каждому защищённому разделу — проверка роли текущего пользователя на сервере |

---

## 3. Визуальный стиль

- Пастельные, светлые оранжевые оттенки
- Единый стиль на всех страницах
- Адаптивная вёрстка через Bootstrap 5.3

---

## 4. Роли в системе

1. **Гость** — неавторизованный посетитель
2. **Пациент** — роль по умолчанию при регистрации
3. **Врач**
4. **Регистратор**
5. **Администратор**

---

## 5. Функциональные требования

### 5.1. Гость

#### Открытый функционал (доступ без авторизации)
- Главная страница клиники
- Каталог услуг: для каждой услуги — название, описание, изображение, стоимость
- Контакты и график работы клиники
- Блог: список коротких статей с заголовком, текстом и изображением

#### Шапка сайта
В правом верхнем углу:
- Кнопка «Регистрация»
- Кнопка «Авторизация»

#### Регистрация
1. Поля формы: фамилия, имя, отчество, email, пароль, подтверждение пароля
2. Проверка уникальности email; если email уже занят — выводить ошибку, **не стирая данные формы**
3. Индикатор надёжности пароля; при слабом пароле — блокировать переход к следующему шагу
4. При сабмите формы — на бэкенде через PHPMailer/SMTP отправляется email с кодом подтверждения регистрации
5. Код действителен **15 минут**
6. После корректного ввода кода (в пределах срока действия) — аккаунт создаётся, ему присваивается роль «Пациент», создаётся сессия, пользователь автоматически авторизуется

#### Авторизация
- Поля: email, пароль
- При неверной паре email/пароль — общая ошибка
- На странице авторизации — кнопка «Восстановить пароль»

#### Восстановление пароля
1. Пользователь вводит свой email
2. На email отправляется код восстановления (PHPMailer/SMTP)
3. Пользователь вводит код на сайте
4. Если код корректен — открывается форма с полями «Новый пароль» и «Повторите пароль»
5. После нажатия «Сохранить пароль» пользователь автоматически входит в свой аккаунт

---

### 5.2. Пациент

#### Шапка сайта
В правом верхнем углу — вместо кнопок «Регистрация» / «Авторизация» отображается кнопка с сокращённым ФИО: **«Фамилия И.О.»** (например, «Иванов И.И.»). Клик по кнопке открывает страницу профиля.

#### Страница профиля пациента

**Над списком записей** — две кнопки:
- **«Записаться»** — открывает мастер записи на приём (см. ниже)
- **«Мед. карта»** — открывает PDF, объединяющий все протоколы приёма пациента

**Предупреждение об ограничениях:**
Если у пациента есть запись со статусом «Создана» — над кнопками и историей выводится **красная надпись** о том, что при неявке на пациента будут наложены ограничения по самостоятельной онлайн-записи на неделю.

**Список истории посещений** (сверху вниз: от новых к старым):
Каждая запись содержит:
- Дата и время приёма
- ФИО врача
- Статус записи

Поведение по статусам:
- У записей в статусе **«Создана»** — маленький красный крестик в правом верхнем углу. Клик → модальное окно с подтверждением отмены: «Нет» закрывает окно, «Да» отменяет (удаляет) запись.
- Клик по записи в статусе **«Завершена»** → модальное окно со списком оказанных услуг и тремя элементами:
  - Кнопка **«Протокол приёма»** — открывает соответствующий PDF
  - Кнопка **«Чек»** — открывает соответствующий PDF
  - Кнопка закрытия окна

#### Мастер записи на приём (модальные окна)
1. Выбор врача из списка
2. После выбора врача — открывается его расписание; пациент выбирает день, в котором есть свободные слоты
3. После выбора дня — список свободных временных слотов (например, «12:30–13:00»)
4. Клик по слоту → отдельное модальное окно с подтверждением записи
5. «Нет» — окно закрывается, ничего не происходит. «Да» — оба модальных окна закрываются, новая запись появляется в истории посещений со статусом «Создана»

#### Автоматические уведомления (бэкенд)
- **За день до приёма** пациенту автоматически отправляется email-напоминание о записи

---

### 5.3. Расписание врачей (общая модель)

- **Рабочее время:** с 10:00 до 18:00
- **Перерыв:** с 14:00 до 15:00 (слотов нет)
- **Длительность одного слота приёма:** 1 час
- Итого слотов в день у одного врача: **7** (10:00–11:00, 11:00–12:00, 12:00–13:00, 13:00–14:00, 15:00–16:00, 16:00–17:00, 17:00–18:00)

---

### 5.4. Статусы записей (общая модель)

| Статус | Цвет | Кто и когда выставляет |
|---|---|---|
| Создана | Зелёный | Автоматически при создании записи пациентом |
| Подтверждена | Зелёно-серый (ближе к зелёному) | Регистратор — при прибытии пациента в клинику ко времени приёма |
| Исполнена | Серо-зелёный (ближе к серому) | Врач — по завершении всех манипуляций приёма |
| Завершена | Серый | Регистратор — после завершения приёма и оплаты услуг |
| Не явка | Красный | Регистратор — при неявке пациента |

Последовательность **Создана → Подтверждена → Исполнена → Завершена** визуально должна образовывать градиент от зелёного к серому. «Не явка» — отдельный (красный) терминальный статус.

---

### 5.5. Врач

#### Страница врача
Клик по кнопке с инициалами открывает страницу-расписание врача: интерактивный календарь, в котором показаны все его слоты приёма пациентов.
- Занятые слоты выделены цветом и содержат фамилию и инициалы пациента

#### Модальное окно записи (клик по занятому слоту)
- Сверху — ФИО пациента и текущий **статус записи**
  - По окончании приёма врач должен переключить статус с «Подтверждена» на «Исполнена»
- Список **всех услуг клиники** с чекбоксами (по умолчанию выключенными). Врач отмечает услуги, оказанные пациенту в этом приёме
  - Клик по названию услуги также переключает чекбокс
- Кнопка **«Добавить протокол приёма»**:
  - До создания протокола — отображается эта кнопка; клик ведёт на страницу написания протокола
  - После сохранения протокола — на её месте отображается кнопка **«Открыть протокол приёма»**, открывающая ранее созданный протокол в виде PDF

#### Страница протокола приёма
Заготовленная форма, в которую **автоматически подставляются**:
- ФИО пациента
- ФИО врача
- Оказанные услуги
- Дата и время приёма

Врач **вручную заполняет**:
- Поле «Протокол приёма»
- Поле «Рекомендации»

После нажатия «Сохранить» — пользователь возвращается на свою страницу с **открытым** модальным окном этой записи (теперь там — кнопка «Открыть протокол приёма»).

---

### 5.6. Регистратор

#### Страница регистратора
Аналогично странице врача — интерактивное расписание-календарь, но **над ним добавлен селектор выбора врача**: регистратор может переключаться между расписаниями разных врачей.

#### Клик по свободному слоту
- Модальное окно с выбором пациента, которого регистратор хочет записать
- Кнопка **«Записать»** — запись создаётся
- Кнопка **«Отмена»** — окно закрывается

#### Клик по занятому слоту — модальное окно записи
Содержит:
- ФИО пациента
- **Статус записи** — отображается с возможностью изменения через выпадающий список
- Список оказанных услуг
- **Способ оплаты** — выпадающий список: «Наличными», «Картой»
- Кнопка **«Отменить запись»** — при нажатии открывается модальное окно с подтверждением отмены
- Кнопка **«Оплатить»**:
  - **Неактивна**, пока не выбран способ оплаты И пока статус записи не «Исполнена»
  - При нажатии — генерируется и открывается в новой вкладке PDF-чек, содержащий: реквизиты клиники, ФИО пациента, список и стоимость оказанных услуг, общую сумму, способ оплаты
  - После нажатия запись автоматически переводится в статус «Завершена»

---

### 5.7. Администратор

Клик по кнопке с инициалами открывает страницу администратора.

#### На странице администратора
- Управление пользователями: смена ролей (например, пациент → врач, и т.п.)
- Просмотр различной статистики

#### Особенности администратора в общих разделах
- **Блог**: при открытии страницы блога администратор может создавать новые статьи, редактировать и удалять существующие
- **Каталог услуг**: при открытии каталога администратор может добавлять новые услуги, редактировать и удалять существующие

---

## 6. Общие требования

- **Выход из аккаунта** — у каждого авторизованного пользователя на странице профиля должна быть кнопка выхода
- Все PDF-документы (протокол приёма, чек, мед. карта) генерируются на бэкенде
- Все проверки прав доступа выполняются на стороне сервера (не только в UI)

---

## 7. База данных

Спроектировать нормализованную схему MySQL 8.2 под все описанные сущности (пользователи и их роли, услуги, расписание/слоты, записи, статусы, протоколы приёма, чеки, статьи блога, коды подтверждения email и восстановления пароля и т.д.).

Подготовить **SQL-скрипт**, готовый к импорту через phpMyAdmin, включающий:

**Схему (`CREATE TABLE`)**

**Тестовые данные (`INSERT`)**:
- **1 администратор**
- **1 регистратор**
- **2 врача**
- **Несколько пациентов**
- **Записи** к этим пациентам — заполнить все необходимые таблицы так, чтобы были представлены записи в разных статусах
- Несколько услуг в каталоге
- Несколько статей в блоге
